# Sprint 1 Retrospective

## Date

24/08/2026

## Participants

- Member 1
- Member 2
- Member 3
- Member 4

## What Went Well?

- The team successfully completed all four planned Sprint 1 user stories.
- Registration, login, logout, and profile view/update functionality were successfully implemented.
- Frontend and backend development were coordinated successfully during feature integration.
- GitHub branches were used to separate development work for different features.
- Pull requests and feature integration helped the team combine the completed work.
- The tester completed testing for the registration, login, logout, and profile functionality.
- Login functionality was tested separately at the frontend, backend/API, and integration levels.
- The team maintained testing reports for the completed features.
- Jira was used to manage user stories, tasks, and subtasks throughout the sprint.

## What Didn't Go Well?

- Some development and integration tasks took longer than initially expected.
- Coordination between frontend and backend development caused some delays during integration.
- Some testing activities were started after the related development work was completed instead of being planned alongside development.
- The team needed additional time to understand and manage Git branches and remote branches correctly.
- Jira updates were not always made immediately after completing development or testing tasks.
- Some tasks required additional communication between team members before they could be completed.

## What Will We Improve in Sprint 2?

- The team will define and discuss API requirements between frontend and backend developers before implementation starts.
- Testing will be planned and started earlier during feature development rather than waiting until all development is completed.
- Developers will communicate integration requirements and changes with the tester earlier.
- Git branching and pull request procedures will be agreed upon before starting Sprint 2 development.
- Team members will update Jira issues more consistently as soon as their assigned work progresses or is completed.
- Larger tasks will be divided into smaller subtasks where possible to make progress easier to track.
- The team will communicate more frequently when a member is blocked or requires assistance.
- Sprint 2 work will be reviewed regularly to identify delays early.

## Retrospective Conclusion

The team successfully completed all planned Sprint 1 user stories and established the core authentication and profile functionality for Peer Circles. The sprint also helped the team improve its understanding of GitHub collaboration, Jira task management, feature integration, and QA testing.

For Sprint 2, the team will focus on earlier communication, better coordination between development and testing, more consistent Jira updates, and improved task planning.
