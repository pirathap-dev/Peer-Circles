# Peer Circles — Definition of Done

A Product Backlog Item is considered Done only when all applicable criteria below have been satisfied.

## Development

- [ ] The functionality has been implemented.
- [ ] The implementation follows the agreed project architecture.
- [ ] The code has been committed to the GitHub repository.
- [ ] The relevant branch/pull request has been reviewed where applicable.
- [ ] Frontend and backend integration has been completed where required.
- [ ] Database integration has been completed where required.

## Acceptance Criteria

- [ ] All acceptance criteria for the user story have been satisfied.
- [ ] The intended user flow works as expected.
- [ ] Appropriate validation has been implemented.

## Testing

- [ ] Test cases have been prepared.
- [ ] Functional testing has been completed.
- [ ] Relevant UI/API/integration testing has been completed.
- [ ] Identified defects have been documented.
- [ ] Critical/high-priority defects have been resolved or explicitly accepted by the Product Owner.
- [ ] Regression testing has been performed after relevant fixes.

## Product Owner Acceptance

- [ ] The Product Owner has reviewed the completed functionality.
- [ ] The Product Owner confirms that the acceptance criteria have been satisfied.

## Documentation

- [ ] Relevant documentation has been updated.
- [ ] GitHub issue/task has been updated.
- [ ] Evidence of testing and completion has been collected.

Only when the applicable criteria are satisfied will the item be moved to the Done column.
